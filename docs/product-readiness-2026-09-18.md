> **评估视角**：产品经理（不是工程评审）——关注「用户能不能用上、会不会用、敢不敢用、装不装得上」
> **证据来源**：本仓库实测数据（611 个测试函数、真 coverage.py 60.2%、npm/PyPI 实际探测、CLI 20 个命令、123 个工具）

## 0. 结论摘要

**工程质量已达「可交付候选」（8/10），产品层面仍是「单人自用工具」（5/10）。**

最致命的问题不是代码，而是**任何真实用户都还看不到这些改进**：

- PyPI 上的 `0.1.7` 是审计**之前**的代码（对应 commit `bd0e180`）；
- npm 包 `uiu-agent` 在 registry 上**不存在**（`npm view` 返回 404）；
- 本地 **25 个 commit 未推送**，CHANGELOG 的 `[Unreleased]` 段已有 **162 行**。

一句话给决策：**工程质量已经不像 demo 了，产品成熟度卡在「东西没发出去 + 装机路径太重」这两点**——
而这两点都不是编码能力问题，是可以在一两周内解决的**分发与取舍**问题。

## 1. 产品定位与目标用户

**它是什么**：常驻本机、替你动手的**个人 IP agent**——带人设（SOUL.md）、跨会话记忆、技能沉淀、
桌面/微信自动化、定时任务与消息渠道。

| | 说明 |
|---|---|
| **目标用户** | 中国大陆 · Windows · 愿意自备 API key 的个人用户；有重复桌面操作诉求（表单/微信/报表/宏） |
| **不服务的用户** | Linux/macOS（未验证）· 非中文用户（明确仅简体中文）· 企业多租户/合规场景（无隔离） |
| **差异化** | 桌面与微信自动化 + 宏 + 屏幕 OCR —— 这是同类 agent 框架普遍没有的能力 |

## 4. 阻断发布的 5 件事（按 PM 优先级）

### ① 推送 + 发版（唯一「做了等于没做」的问题）
25 个 commit 未推送，用户装到的还是审计前的代码：**安全默认、原子写、备份、回收站全部没有到达用户**。
> 验收：`git push` 后方可进行；随后 `uiu publish` 出一个 0.2.0。

### ② npm 包名落地
`npm view uiu-agent` → 404。npm README 首页承诺的「用户只装 npm、不装 Python」**目前不可兑现**。
> 验收：`npm install -g uiu-agent && uiu version` 在新机器上成功。

### ③ 用真 key 跑一次端到端
核心价值（对话 + 工具编排）至今只有**假 client 的单测**覆盖。仓库已有 `live` 标记的 E2E
（`UIU_E2E_LIVE=1`），但本机没有 key，从未运行。
> 验收：`UIU_E2E_LIVE=1 pytest tests/test_e2e_live_llm.py -m live` 两条用例通过。

### ④ 依赖瘦身 / 首次安装成功率（最大不确定性）—— ✅ 已解决（2026-09-18）

核心依赖从 **18 个收到 8 个**（openai / anthropic / rich / prompt-toolkit / textual / pyyaml /
psutil / pyperclip），重依赖全部进 extras：`[desktop]`（pyautogui/pillow/pywin32/numpy/opencv）·
`[ocr]`（rapidocr-onnxruntime/screen-ocr）· `[office]`（openpyxl）· `[channels]`（slack-bolt/cryptography）
· `[browser]` / `[voice]` / `[rag]` / `[mcp]`。

**实测（全新 venv，Python 3.14，国内镜像）**：

| | 之前 | 现在 |
|---|---|---|
| `pip install -e .` | 30 分钟以上**未装完** | **132 秒 / rc=0 / 31 个包** |
| 核心-only 能否跑 | —— | ✅ `version` / `init` / `doctor --lint` / `--json` / 123 工具注册全部正常 |

分层判据不是「谁被 import 过」，而是**启动路径上是否真的必需**：屏蔽全部 35 个可选库后，
24 个核心模块（config/sessions/agent/tools/main/app/gateway/cron/doctor/…）仍全部导入成功。
这条判据以测试固定下来（`test_core_dependencies_stay_small`、
`test_heavy_stacks_never_leak_back_into_core`、`test_core_imports_do_not_need_optional_extras`）。

顺带修掉一处**静默降级**：OCR 缺依赖时 `screen_read_text` 原本回「屏幕上没有识别到文字」
（会让用户以为屏幕真没字），现在明确回「OCR 能力未安装…pip install 'uiu[ocr]'」。

> 剩余差距：132 秒离「1 分钟」还有距离（主要是 pydantic-core/jiter 等 Rust wheel 与镜像延迟）。
> 若要继续压，方向是把 `anthropic` 也变成 extras（只留 openai），但那会让 Claude 用户多一步。

### ⑤ 平台与语言边界前置
现在写在 `docs/platform-support.md` 与 README 中段。mac/Linux 用户装完才发现桌面能力全不可用。
> 验收：README 首屏出现「Windows 一等公民 / 仅简体中文」两行。

## 5. 风险清单

| 类别 | 风险 | 缓解 |
|---|---|---|
| 产品 | 单人维护、零用户、零反馈循环；同类在**生态**（skill 源/插件/云同步）领先 | 先发内测版拿真实崩溃样本 |
| 技术 | 桌面自动化强依赖本机状态（DPI/输入法/杀软/窗口层级），**只在开发机验证过** | 找 2–3 台异构机器跑安装 + 桌面用例 |
| 安全 | API key 明文 `.env`；网关一旦为接微信回调对外暴露只剩一道 token；prompt injection 仅「高风险需确认」一层 | 接系统凭据库；注入防线提到「外部内容触发的工具调用需确认」 |
| 合规 | ~~产品会读屏幕、读文件、读微信消息，却没有隐私/数据处理声明~~ | ✅ **已解决**：`docs/privacy.md` 写清数据存哪/发给谁/风险/清理手段，并有测试守住「无遥测」与「出站主机必须已在文档登记」 |
| 分发 | npm 会下载并执行远程 Python 运行时，供应链风险需说明 | 固定版本 + 校验和 + 镜像可配（现状已有镜像开关） |

## 6. 决策选项与建议

| 选项 | 内容 | 判断 |
|---|---|---|
| **A. 立刻发 0.2.0-beta** | 推 PyPI + 自用一周 | **建议先做**：不发布就永远没有真实反馈；已经在无用户状态下优化了 15 轮 |
| **B. 补齐再发** | 依赖瘦身 + 安装成功率 + 隐私声明 | 与 A **并行**；依赖瘦身是唯一需要多轮的不确定项 |
| **C. 生态优先** | npm 落地 + skill 商店抢装机量 | 放在 A 之后：装机量是结果，不是前提 |

**建议动作顺序**：① 推送 → ② 依赖分层 → ③ 发 0.2.0-beta + npm 0.2.0 → ④ 隐私声明 → ⑤ 真 key live E2E。
前三项做完，「用户能拿到新代码」与「首次安装成功率」这两个最致命的问题即解除。
